# VLA 模型评测报告（飞书多维表格直连）

## 这个 skill 做什么

用户给模型名，你产出一份 6 节报告，**最终发布成飞书文档交付**（本地 md 只作中间稿）。两种模板：**双对比测试报告**（一个基准对 1–7 个模型）和**单测试报告**（一个模型的绝对水平）。数据**直接从飞书多维表格读**，不导表、不落地 Excel。

**所有统计数字必须来自本工具包的程序。不得心算、换算、四舍五入任何数字。**

## 路径约定（装在技能目录里时必读）

- `SKILL_DIR` = 本 `SKILL.md` 所在目录。先用 `pwd` 或文件路径确认它，然后**所有命令都用绝对路径**：`node "$SKILL_DIR/cli.js" …`、`python3 "$SKILL_DIR/verify.py" …`。调用方 cwd 不确定，不要用相对路径。
- **输出一律写到用户可写目录**（用户项目目录 / 桌面 / 当前工作目录下的 `报告输出/`），每轮新建 `报告输出/<标题>/work_YYYYMMDD-HHMM`（`date +%Y%m%d-%H%M`）。**绝不写进 `SKILL_DIR`**——技能目录在多数环境里是只读的，写进去会直接失败。
- 本 skill 自带的 `compute-lock.json` 是随包发布的指纹基线，**不要改它**。

## 不适用

- 只是临时瞄一眼某个模型的数字、不要成稿 → 用单测试报告（`--type single`），看 `_结果.json` 就够，不必写正文。
- 用户要的是「这个模型测成什么样」而不是「比上次好多少」→ 用 `--type single`，不要套对比模板硬写方向。
- 数据还在本地 xlsx、没有对应多维表格 → 走原版路径（`node "$SKILL_DIR/cli.js" 白盒.xlsx 黑盒.xlsx --models …`），其余流程相同。
- 用户要 PPT/Word → 先生成 `.md` 报告，再按要求的载体转换。

## 开工前检查（缺一不可，不要绕过）

```bash
node -v                                        # 需要 18+
python3 -c "import numpy, scipy"               # 缺则 pip3 install numpy scipy
node "$SKILL_DIR/cli.js" --lock-status         # 必须 ✅
lark-cli base +table-list --base-token YOUR_BASE_TOKEN --as user --limit 1 >/dev/null && echo ok
```

`--lock-status` 不是 ✅ 时**停下来**（处理方式见下节）。lark-cli 读表用的是**当前登录账号的身份**：账号对两本多维表格没有读权限时读表会失败，这要去加权限，不能换接口绕过。

## 数据源（由用户提供）

| 用途 | 文档 | base token |
|---|---|---|
| 白盒（ID + 白盒 OOD） | 基模测试记录 | 用户提供 |
| 黑盒（黑盒 OOD） | 基模黑盒场景测试记录 | 用户提供 |

`--base-w` / `--base-b` 接受用户提供的 wiki 链接，程序自动解析到底层多维表格。不要硬编码任何账号或表格标识。

表结构约定（子表名 = 模型名，字段名 = 大表表头）：
- 一个子表一个模型；子表名去掉 `261009-` 这类日期前缀和 `FT测试记录-` / `FT黑盒测试记录-` 前缀后就是模型名。
- 子表名含「黑盒」的按黑盒 OOD 处理，其余按 `0902-ft—ood` 列分成 ID / 白盒 OOD。
- 必需列：`用例ID`、`T1..T5_分数`；其余（`prompt_ch`、`Skill标签`、`T1..T5_标签`、`满分次数`、`0902-ft—ood`、`ood类型`）有就用。
- 子表缺必需列会被跳过并告警；新增子表只要遵守上面的命名和列名，不用改代码。

## 报告类型（`--type`）

| 类型 | 名称 | 模型数 | 用于 |
|---|---|---|---|
| `compare`（默认） | 双对比测试报告 | 2–8（第一个为基准） | 「新模型比基线好多少」，带差值 / 90% 区间 / p 值 / 显著性判词；4 模型以上自动换 N 版式 |
| `single` | 单测试报告 | 1 | 「这个模型测成什么样」，只有水平与分布，无差值无 p 值 |

报告结构由本工具包的渲染器定义。**所有数字只来自 `engine/analyze.js`**；不得为了版式在渲染器里新算任何数字。

## 计算文件指纹锁

程序每次运行（含 `--templates`、`--check`）先比对 `compute-lock.json` 里的 SHA-256，覆盖 `math.js`、`analyze.js`、`native.js`、`report.js`、`report_*.js`、`excel.js`、`verify.py`、`crosscheck.py`。不一致直接 `exit 1`，不出任何数字。

**在技能形态下你没有改它的权限，也不该改：**

- 报 `❌ …：期望 xxx… 实际 yyy…` → 包里的计算文件与发布基线不一致（被改过，或安装包损坏）。**停下来，把差异原样告诉用户，请维护者处理**。不要手改文件、不要动 `compute-lock.json`、不要尝试 `--relock`。
- `--relock` 属于**维护者操作**，只在可写的开发副本里做，并在 `history` 写明原因。技能目录里的副本永远不该被 relock。
- 报 `＋未登记的新文件` → 有人往 `engine/` 里塞了新渲染器。同样停下来告知，不要自己登记。

## 流程（不跳步）

`<work>` 一律绝对路径，落在用户可写目录。

1. **列模型**（用户没说清基准/对比时列出来给用户选，不要自己猜）

   ```bash
   node "$SKILL_DIR/cli.js" --base-w <白盒> --base-b <黑盒> --list
   ```

2. **出数**

   ```bash
   node "$SKILL_DIR/cli.js" --base-w <白盒> --base-b <黑盒> \
     --models "<基准>" "<A>" "<B>" \
     --labels "<基准短名>" "<A 短名>" "<B 短名>" \
     --out <work>
   ```

   **模型名使用易区分的短名**：`--labels` 按 `--models` 顺序给显示名（如 `模型A` / `模型B`）。短名只影响报告渲染，`_结果.json`、`_复核表.xlsx`、`verify.py` 仍用数据源全名匹配。不给 `--labels` 时报告里就是全名。

   三模型：`--models "<基准>" "<A>" "<B>"`，A、B 各自对基准，不做 A vs B 互比。
   四模型及以上：`--models "<基准>" "<A>" "<B>" "<C>" …`（最多一个基准 + 七个对比），每组各自对基准；3 组对比以上自动改用 N 模型版式（`engine/report_n.js`）：仍是固定 6 节，§2 范围表列出全部对比组，§4–§6 每组各成一块。
   单测试报告：`--models "<模型名>" --type single`。
   白盒/黑盒子表名不一致时写成 `"白盒名|黑盒名"`。
   终端里的 📄 行和 ⚠️ 警告（漏测、只有白盒或黑盒、满分次数对不上、执行加权与配对均差方向相反）**原样转告用户**。
   产出：`_数字底稿.md`、`_结果.json`、`_复核表.xlsx`、`_输入长表.xlsx`。

3. **独立复算**

   ```bash
   python3 "$SKILL_DIR/verify.py" <work>/..._结果.json     # 必须「不一致 0 项」
   ```

4. **写报告**：按程序生成的数字底稿组织结论和各节内容，数字只从底稿原样复制。§1 核心结论可由子代理 `vla-conclusion` 写进 `<work>/s1_conclusion.md` 并留 `s1_conclusion.done`，用 `python3 "$SKILL_DIR/assemble.py" <work> <报告.md>` 拼装；结论撰写方另写 `<work>/s0_core.md`（标题下一句话，不带统计数字）时由 assemble 做成 callout，没写就沿用底稿自动结论；用户给了测试配置就写 `<work>/s3_config.md`。没有该子代理时根据底稿数字撰写，并复核每项数字。

5. **逐数核对**

   ```bash
   node "$SKILL_DIR/cli.js" --check <work>/..._数字底稿.md <报告.md>
   ```

   `🚫` 永久禁用语句必须删除（无豁免）；`❌` 的数字逐个说明来源或改掉，直到 `✅` 或剩下的全是能说明来源的非统计数字。

6. **跨报告核对**（有模型在旧报告里出现过时）

   ```bash
   python3 "$SKILL_DIR/crosscheck.py" <work>/..._结果.json
   ```

   必须「✅ 重合模型全部一致」，否则停下来查（大表是否更新、是否换过子表、标签是否改过）。

7. **发布成飞书文档**（交付物，不是可选步骤）

   ```bash
   python3 "$SKILL_DIR/publish.py" <报告.md> --title "<标题>" --doc <已有文档 id>
   ```

   **优先原地改**：用户已有这份报告的文档（或说「在已有的基础上改」）时，必须带 `--doc`（文档 id 或 URL），用 `docs +update --command overwrite` 覆盖正文，链接不变、不新建第二份文档；只有首版或规则维护要新文档时才不带 `--doc`。

   只做版式搬运：取首行 `# 标题` 作为文档标题并从正文去掉、§1 若没 `<callout>` 自动补一层、其余原样导入。**不改任何数字、不新增段落**。命令会打印文档链接与 id，链接就是最终交付物；本地 md 留在 `<work>` 里作 `--check` 的核对基准，不发出去。
   发布失败（无云文档权限、空间不足、企业策略拦截）→ 把报错原样给用户，**不要**改用本地 md 冒充交付，也不要自己换账号。

8. **交付**：飞书文档链接 + 一句话结论；数据指纹前 16 位（只口头说，不写进报告）、verify 结果、核对结果、跨报告核对结果、豁免的非统计数字及来源。

## 硬规则

- §1 结论用「加粗一行 + 三条 bullet」，**不用引用块（`>`）**，也不重复 callout 那句结论。
- 报告六节：结论 / 统计说明 / 测试配置对比 / 核心指标对比 / 能力维度 / 问题标签；**章节用飞书标题块自动编号**（发布后显示 1. / 4.1 / 4.2.1，md 里只写 `##` `###` `####`，不写字面数字）；文档标题下先用 callout 写一句核心结论。
- 结论节句式照定稿：模型名在句首，指标只写「满分率从 X → Y（+Δ，p=）」，判词收在句尾。
- **§1 用 `<callout emoji="⭐">` 包裹**，组内是一段背景 + 每组对比一条加粗结论 + 一条排序句，与历史报告一致；不要把三条指标逐字念一遍。
- **最终交付是飞书文档链接**；本地 md 只是中间稿与 `--check` 的基准，不作为交付物发给用户。
- **Skill 小类按标签拆分**：一个用例同时带「抓取」和「双手协同」时，两个小类各计一次，不合并成「抓取 双手协同」。§5 各行用例数之和会大于总用例数，属正常。
- **§4.1 可附「显著变化用例（ID）」表**，列出用例 ID 与 prompt 供用户回查；归因列留空，由测试人员填写。OOD 切面也可按相同格式列出变化用例。
- 表格样式由 `publish.py` 处理；差值列的颜色由程序决定，不要手改；emoji 只准出现在 callout 图标位。
- 数字一律原样复制底稿的小数位与格式；底稿没有的数不写。
- 禁用语句（数据指纹块、三指标取舍声明、人工占位、各类免责声明）不进报告正文。
- 多轮生成不复写旧报告：重跑程序，新时间戳新文件，旧版保留。
- 水平按有效执行加权，只有 p 和 90% 区间用两边都有的用例配对；差值 = 两边原始水平相减再舍入。
- 单模型报告不写方向性判词（显著 / 上升 / 下降）；没有对比对象，这类判断无法由数据得出。
- 不修改 `engine/`、`verify.py`、`crosscheck.py`、`compute-lock.json`。需要新报告类型时告诉用户去找维护者，由维护者在开发副本里新增渲染器并 relock 登记。

## 常见故障

| 现象 | 原因 / 处理 |
|---|---|
| `找不到计算文件指纹清单` / 列表不一致 | 安装包不完整或文件被改；停，原样告知用户，找维护者重新发一份 |
| `未知报告类型「…」` | `--type` 写错；`node "$SKILL_DIR/cli.js" --templates` 看可用值 |
| `单测试报告只接受一个模型` | `--type single` 时 `--models` 只能给一个；要比两个就去掉 `--type` |
| `读取「…」缺少「用例ID」…已跳过` | 子表不是模型记录表，或列名被改过；确认列名 |
| `没找到模型「X」对应的 sheet` | 子表名与模型名对不上（多套了一层前缀）；用 `--list` 看实际模型名 |
| 读表报权限错误 | 当前账号对这本 Base 没有读权限，让用户加权限，不要换接口绕过 |
| `verify.py` 出现不一致 | 数据被改过或抽表逻辑异常，停下来查，不要带着不一致出报告 |
| 同一模型有多份子表 | 程序只取第一个，会被警告；让规则维护用哪份 |
| 输出目录写入失败 | 写到了只读的 `SKILL_DIR`；改写到用户可写目录 |
| 发布报 `permission denied` / `forbidden` | 当前账号没有云文档创建权限，或目标文件夹受限；如实告知用户，不要换账号或退回本地 md 交付 |
| 发布后的文档缺表格 / 表格变成文本 | Markdown 表格必须标准（表头 + `|---|` 分隔行，列数一致）；检查 `_发布稿.xml` 与 `_发布稿.md` 再重发 |
