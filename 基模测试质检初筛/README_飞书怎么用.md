# 基模测试质检初筛：飞书版

这个包把质检初筛做成 `SKILL.md`，给飞书里的 AI 用；同时提供脚本版做确定性批量检查、原版/终版对账和闭环审计。

## 包里有什么

| 文件 | 用途 |
|---|---|
| `SKILL.md` | 飞书 AI 的规则、执行流程、输出和闭环要求 |
| `规则表.md` | R1～R11、V1～V5、S1～S4 的条件与出处 |
| `标签共存矩阵.csv` | 共标检查唯一来源；0 分也检查 |
| `baseline.json` | 空白历史基线结构；请从有权使用的数据自行生成 |
| `原理与计算方法.md` | 指标口径与适用限制 |
| `prescreen.py`、`脚本版说明.md` | screen / compare / audit / baseline |
| `test_prescreen.py` | 合成回归测试 |
| `baseline.json` | 历史基线文件；仓库仅提供空结构 |

## 装到飞书里

1. 建一个名为「基模测试质检初筛」的 AI 助手或技能。
2. 将 `SKILL.md` 全文放入指令；不要只保留旧版绝对分数规则。
3. 将 `规则表.md`、`标签共存矩阵.csv`、`原理与计算方法.md` 放入可读取的知识或文件中。
4. 如需 V5 历史偏差复核，先用自己有权使用的历史数据生成基线；无基线时仍可运行静态规则。
5. 授权读取测试记录。若要做闭环，还要能保存原版、终版和复核回执。

## 第一次用：先验收

先跑脚本回归：

```bash
python3 test_prescreen.py -v
```

再在飞书中试一个 sheet，重点核对：

- 0 分的「具体失败标签 + 重试完成/过度执行」也会退回，不因分数为 0 跳过。
- 报告写出实际冲突组合，而不是只写规则编号。
- 有历史且用例均分偏差达到阈值时标 V5；只说异常复核，不建议改分。
- 分数空但有详情仍是合法不打分；没测的整行仍跳过。
- 默认盲抽 20% 且至少 5 个，并写出样本量和发现能力。
- 每个推荐和盲抽都有待处理回执；退回未处理会一直出现在未闭环清单。

本仓库不包含真实测试记录或历史统计。合成回归测试只验证规则与程序行为，不代表实际数据分布。

## 每天怎么用

1. 测试员录完一个 sheet。
2. **QC 开始前复制一份，命名为「原 sheet 名-原版」**。
3. 对飞书 AI 说：「初筛一下『xxx』这个 sheet」。有新测试员时同时给名单。
4. 按报告处理：退回给测试员，QC 看必复核和抽检，盲抽按正常标准看。
5. 每个推荐或盲抽用例都填写回执：状态、是否修改、修改类型（分数/标签/判词）、复核人、复核时间。
6. 跑闭环审计；有未闭环项就不能说本批完成：

```bash
python3 prescreen.py audit out/xxx_复核回执.csv --require-closed
```

7. QC 后有原版和终版时跑精确对账：

```bash
python3 prescreen.py compare 表.xlsx 表.xlsx \
  --orig-sheet "xxx-原版" --final-sheet "xxx"
```

compare 会把「仅改判词」计入改动和召回；audit 则用回执给未闭环、盲抽漏检和抽样估计召回。两者不要混用：精确召回看 compare，日常闭环与抽样估计看 audit。

## 要知道的限制

- 飞书 AI 需要逐条检查数百次试验，数数可能出错；规则以脚本版为准，两者不一致时先查脚本结果。
- 规则效果需要用使用者自己的独立复核数据评估，不从合成测试推断实际效果。
- 新增规则、判词口径和盲抽策略都应通过后续回执重新评估，不预设提升数字。
- 少量盲抽发现 0 个问题不等于漏检率为 0；看 Wilson 区间、发现能力并跨批累计。
- 历史均分只通过 V5 提示异常，不用于自动改分；人工难度仍只作参照。
